# Dialogue State Tracking (DST) Architectures, incl. Speech-Aware DST

## What is the core idea of SOM-DST? How does it represent dialogue state as memory, decide overwrite vs. keep, and what are its limitations?

### Takeaway
SOM-DST (Kim et al., ACL 2020) treats the dialogue state as a fixed-size slot-value memory that is read turn-by-turn and *selectively* overwritten: a small "state operation predictor" decides, per slot, whether to keep, delete, mark dontcare, or regenerate the value, and only the slots marked for update are passed to a generator — this is efficient but makes the operation-classification step the dominant source of error, and the overwrite is a one-shot, non-reversible commit rather than a revisable belief.

### Cited Findings
- SOM-DST decomposes DST into two jointly-trained sub-tasks: "state operation prediction," which decides the operation (CARRYOVER, DELETE, DONTCARE, UPDATE) for each memory slot, and "slot value generation," which generates new values only for the subset of slots marked UPDATE — in contrast to prior work that generated/extracted values for *all* slots every turn. — [arXiv abs/1911.03906](https://arxiv.org/abs/1911.03906)
- The dialogue state is explicitly modeled as a fixed-sized memory; each turn the model reads the previous-turn memory plus the current turn's dialogue utterance and either carries a slot's value over unchanged or overwrites it. — [arXiv abs/1911.03906](https://arxiv.org/abs/1911.03906)
- SOM-DST reports 51.72% joint goal accuracy (JGA) on MultiWOZ 2.0 and 53.01% on MultiWOZ 2.1 in the open-vocabulary DST setting, state-of-the-art at publication; the authors note that improving state-operation prediction specifically has the largest potential to raise overall accuracy. — [ACL Anthology 2020.acl-main.53](https://aclanthology.org/2020.acl-main.53/)
- Error-propagation analysis (from predicted, not ground-truth, prior state) roughly doubles total error versus using ground-truth prior states: error propagation increases absolute error by ~2.47x. — [search aggregation citing SOM-DST error analysis](https://www.google.com) (secondary synthesis; see Gaps)
- Decomposing where errors originate: with error propagation, ~78–93% of absolute error is attributable to the state-operation predictor and ~7–22% to the slot-value generator (components overlap, hence the ranges); without error propagation (oracle prior state), the split is similar (~90% operation predictor, ~20% value generator). — [arXiv pdf/1911.03906 as aggregated via MDPI RSP-DST analysis](https://www.mdpi.com/2079-9292/12/6/1494) *(could not directly fetch MDPI page — this figure came through a search snippet referencing the RSP-DST paper's re-analysis of SOM-DST; treat as secondary until verified against the primary PDF)*
- A follow-up paper, RSP-DST ("Revisable State Prediction for DST"), is motivated explicitly by a limitation of the state-operation framing: once an operation like DELETE/CARRYOVER is committed for a turn, errors in that decision are not easily revisited in later turns — RSP-DST's title and framing ("revisable state prediction") signal that non-revisability of per-turn memory operations is treated as an open problem by later work, not a solved one. — [MDPI 2079-9292/12/6/1494 search result](https://www.mdpi.com/2079-9292/12/6/1494)

### Inferences
- SOM-DST's central reusable abstraction — *maintain a persistent structured memory; each turn, classify "what kind of change is this" before deciding "what the new value is"* — is domain-agnostic in principle (it doesn't require slots to mean restaurant/hotel/train fields specifically). The dependence on a *fixed-size, enumerable slot memory*, however, is the domain-specific/schema-specific part: the operation predictor has a fixed output head per slot, so adding a new slot type requires retraining that head.
- Because operation prediction is both the main efficiency win (avoid regenerating everything) and the main error source, the core engineering trade-off this architecture family embodies is: deciding *what changed* is harder and more consequential than generating *the new value* once you know something changed. This is likely to generalize to any "persistent state + turn-level update" design, including a schema-free one.
- The one-shot overwrite (no explicit mechanism to hold two competing hypotheses or revisit a previous commit) suggests memory-overwrite-style DST, as a family, treats state as a single committed belief rather than a distribution — contradiction/correction has to be handled by *re-running* the same update mechanism on a later turn, not by an explicit "retract" operation with memory of the prior alternative.

## What is MultiWOZ, and what has task-oriented DST research built on it established about persistent state, cross-turn revisions, and multi-domain generalization? What are the dominant DST architecture families?

### Takeaway
MultiWOZ is the de facto multi-domain task-oriented dialogue benchmark (7 domains: restaurant, hotel, attraction, taxi, train, hospital, police); successive "cleanup" releases (2.1, 2.2, 2.3, 2.4) exist specifically because the original annotations of persistent, cross-turn, cross-domain state were noisy and inconsistent, which is itself a strong signal about how hard reliable state-persistence annotation is even for humans. DST architectures built on it cluster into four families — classification/picklist (fixed ontology), span-extraction, open-vocabulary generative, and schema/description-driven — and a fixed slot ontology is treated by the field as a simplifying assumption of the *benchmark*, not a theoretical requirement of DST itself.

### Cited Findings
- MultiWOZ contains ~8,438–10,000+ multi-turn human-human dialogues across 7 domains (restaurant, hotel, attraction, taxi, train, hospital, police) and is described as the largest/most-used multi-domain TOD dataset, becoming the de facto benchmark for DST, NLU, and dialogue policy research. — [arXiv pdf/1907.01669](https://arxiv.org/pdf/1907.01669); [ACL 2022.sigdial-1.34](https://aclanthology.org/2022.sigdial-1.34/)
- MultiWOZ 2.0's original state annotations were noisy enough to "negatively impact the performance of state-tracking models," motivating MultiWOZ 2.1 (state corrections), 2.3 (co-reference annotation), and 2.4 (further corrections to validation/test sets specifically to improve DST evaluation reliability). — [arXiv pdf/1907.01669](https://arxiv.org/pdf/1907.01669); [ACL 2022.sigdial-1.34](https://aclanthology.org/2022.sigdial-1.34/)
- The MultiWOZ 2.1 correction pass changed over 32% of state annotations across 40% of dialogue turns; of corrected values the breakdown was: no change 98.16%, none→value 1.23%, valueA→valueB 0.44%, value→none 0.17%, value→dontcare 0.23%; name slots (restaurant/attraction/hotel names) had the most spelling-related corrections. — [search aggregation of MultiWOZ 2.1 paper](https://arxiv.org/pdf/1907.01669)
- Two specific persistent-state failure modes the MultiWOZ 2.1 authors identified and fixed: "delayed markups" (a slot value is annotated one or more turns after it was actually mentioned) and "forgotten values" (a value the user stated is never reflected in the gold dialogue state at all). This is direct evidence that *turn-to-turn state persistence/carryover* is a nontrivial annotation and modeling problem even in a fixed-schema setting. — [search aggregation of MultiWOZ 2.1 paper](https://arxiv.org/pdf/1907.01669)
- DST architecture families built/evaluated on MultiWOZ: (1) **ontology/classification-based ("picklist")** — scores a fixed candidate list per slot from a predefined ontology; (2) **span-extraction-based** — extracts the value as a substring/span of the dialogue context (e.g., TripPy's "triple copy strategy": copy from user utterance, system utterance, or a memory of previously-mentioned values); (3) **open-vocabulary generative** — a generator produces the value as free text, not constrained to a fixed candidate list (SOM-DST falls in this family, as does the broader "candidate generation" vs. "span extraction" split noted for open-vocabulary DST); (4) **hybrid** — e.g., DS-DST, which uses picklist-based classification for slots with a small/stable value set and span-extraction for open slots; (5) **schema/description-driven** — e.g., D3ST (Google), which feeds the model natural-language *descriptions* of each slot/intent (with randomized index labels standing in for literal slot names) so that the model is not hard-wired to a fixed slot vocabulary and can generalize zero-shot to unseen slots/services by reading their descriptions. — [arXiv html/2005.02877v2 (TripPy)](https://ar5iv.labs.arxiv.org/html/2005.02877); [researchgate D3ST](https://www.researchgate.net/publication/358144557_Description-Driven_Task-Oriented_Dialog_Modeling); [arXiv pdf/2201.08904](https://arxiv.org/pdf/2201.08904)
- A 2022 survey ("Do you follow me?": A Survey of Recent Approaches in Dialogue State Tracking, Jacqmin, Rojas-Barahona & Favre, SIGDIAL 2022) states the text-to-text (generative) paradigm has become the favored approach in recent DST research, but argues that generalizability of DST models remains underexplored and proposes it as a key open research direction. — [ACL 2022.sigdial-1.33](https://aclanthology.org/2022.sigdial-1.33/)

### Inferences
- The repeated cycle of MultiWOZ 2.0 → 2.1 → 2.2 → 2.3 → 2.4, each pass specifically re-fixing *state* annotations (not utterances), is strong indirect evidence that "what is the correct persistent state at turn t, given carryover/cross-domain/cross-turn revision" is genuinely hard to pin down even for human annotators working from a fixed schema — this is a structural property of multi-turn goal tracking, not an artifact of any one model architecture.
- Picklist/ontology-based and span-extraction architectures are the ones most tightly coupled to a fixed schema (picklist needs an enumerated value set per slot; span-extraction needs slot:span alignment supervision). Open-vocabulary generative and description-driven (D3ST-style) architectures are the ones in this literature that most directly point toward schema flexibility — D3ST's explicit design goal (zero-shot transfer to unseen services via natural-language descriptions rather than hard-coded slot names) is the clearest existing precedent in the fixed-schema literature for a "soft schema" approach, which is architecturally close to what a task-agnostic, schema-flexible state tracker for voice AI would need.
- A fixed slot/value ontology is best read as a convenience for *supervised benchmark construction and automatic scoring* (JGA requires a ground truth of discrete slot:value pairs to compare against), not as evidence that dialogue state must be representable only as fixed slots to be tracked well. The existence of open-vocabulary and description-driven DST within the very same MultiWOZ ecosystem demonstrates the field itself does not treat the fixed ontology as fundamental — see next section for explicitly schema-agnostic/ontology-free work.

A full read would likely surface a more explicit taxonomy of architecture families and a more detailed discussion of open research gaps (I'd flag this for follow-up if deeper depth is needed).

## What does DSTC11's speech-aware track find about DST performance degradation under ASR noise, and what mitigations were tried?

### Takeaway
DSTC11 Track 3 (Speech-Aware Dialog Systems Technology Challenge) replaced clean written user turns with spoken/ASR-transcribed turns (TTS-synthesized train/dev, human-read test) and found severe, specifically-measured JGA degradation from ASR noise — figures reported range from "58.1%→47.2%" to a much starker "53.8%→26.1%" depending on evaluation-set construction — and the strongest mitigations were an explicit ASR-error-correction module, entity-specific post-processing (numbers/times/proper nouns), and training-time ASR-error simulation/data augmentation, rather than relying on the downstream DST model alone to absorb noise.

### Cited Findings
- DSTC11 Track 3 (Speech-Aware DST) replaced written user turns with spoken utterances: TTS-synthesized audio for train/dev and human-volunteer-recorded speech for the test set, then ran ASR over that audio to produce the noisy transcripts DST systems had to consume. — [search aggregation of DSTC11 overview](https://aclanthology.org/2023.dstc-1.10/)
- Reported ASR transcript error rate for the DSTC11 speech-aware condition was about 26.25% (word error rate), described as a significant challenge for downstream DST. — [search aggregation](https://arxiv.org/pdf/2308.15053)
- Reported JGA degradation numbers (two different framings found, worth flagging as potentially from different evaluation subsets/papers — see caveat below): (a) JGA fell from 58.1% (written) to 47.2% (ASR) on an "original" evaluation set; (b) on a separately-constructed "unbiased" DSTC11 evaluation set (dev-dstc11/eval-dstc11), JGA for top models fell much more sharply, from 53.8% (written) to 26.1% (ASR) — the authors behind figure (b) argue the smaller drop in (a) partly reflects that models can "memorize" slot values from the original MultiWOZ test set regardless of ASR noise, which "distorts the effect of ASR errors on the downstream dialog models and paints an overly rosy picture," motivating the construction of the harder unbiased eval set. — [search aggregation re: DSTC11 overview paper and critique](https://arxiv.org/pdf/2212.08704)
- A winning architecture pattern (used by OLISIA, which ranked 1st in DSTC11 Track 3) was a three-part cascade: (1) ASR, (2) an explicit ASR-error-correction stage (e.g., time-expression normalization and named-entity/proper-noun correction applied to the ASR hypothesis), and (3) a text-based DST model (e.g., D3ST-style slot-description model) consuming the corrected transcript, sometimes followed by (4) post-processing to recover/repair slot values. — [GitHub Orange-OpenSource/olisia-dstc11](https://github.com/Orange-OpenSource/olisia-dstc11); [ACL 2023.dstc-1.12 (OLISIA)](https://aclanthology.org/2023.dstc-1.12/); [ACL 2023.dstc-1.10](https://aclanthology.org/2023.dstc-1.10/)
- OLISIA's own ablation (JGA/WER at each post-processing step) on three test conditions (TTS-verbatim, Human-verbatim, Human-paraphrased): raw Whisper ASR gave 37.9/4.92, 33.8/8.4, 32.0 (JGA/WER); after time normalization, 40.0/4.49, 35.6/7.89, 33.5; after proper-noun correction, 40.3/4.36, 36.1/7.71, 34.3. Time normalization gave roughly a 5% relative JGA gain across all three conditions; proper-noun correction helped more on the noisier human-speech conditions (+1.4% and +2.4% relative JGA) than on cleaner TTS speech (+0.75%). — [search aggregation of OLISIA results](https://aclanthology.org/2023.dstc-1.12.pdf)
- A key methodological finding from OLISIA: WER is a poor proxy for how much ASR noise will actually hurt DST, because only a small number of words in a user utterance are actually state-relevant — so the paper explicitly computed JGA (task metric) at every correction step rather than relying on WER improvements alone. — [search aggregation](https://aclanthology.org/2023.dstc-1.12.pdf)
- A second DSTC11-track system ("Adapting Text-based Dialogue State Tracker for Spoken Dialogues") reports a similar three-module recipe: (1) an explicit ASR-error-correction module to bridge spoken/text domain gap, (2) a text-based DST model (D3ST, estimating slots/values via slot descriptions) for the actual state estimation, and (3) post-processing to recover errors in the estimated slot values; the paper's own stated conclusion is that it is "important to use an explicit ASR error correction module, post-processing, and data augmentation" — i.e., none of the three alone is sufficient; they are complementary mitigations. — [ACL 2023.dstc-1.10](https://aclanthology.org/2023.dstc-1.10/)
- Later (2023-2025) follow-on work continues to treat spoken DST robustness as unsolved: "Are cascade dialogue state tracking models speaking out of turn in spoken dialogues?" critiques cascade (ASR→correction→DST) systems' error-propagation behavior, and "Is one brick enough to break the wall of spoken dialogue state tracking?" (2023) argues jointly-optimized/fully-neural end-to-end spoken DST is competitive with cascades, specifically flagging that cascade systems suffer from error propagation and separate-stage optimization, and arguing that training procedures should explicitly account for the previous turn's inherited uncertainty (i.e., propagate a notion of confidence/uncertainty about prior state into the current turn's update, not just a single best guess). — [arXiv abs/2311.04922](https://arxiv.org/abs/2311.04922); [arXiv abs/2311.04923](https://arxiv.org/abs/2311.04923)

### Inferences
- The gap between the "58.1→47.2" and "53.8→26.1" figures is itself an important methodological finding, not just noise in my search: it suggests that *how you construct the evaluation set* (whether it allows models to rely on memorized slot-value strings from the original clean MultiWOZ test set) can make ASR-robustness look far better than it really is. Any "conversational integrity layer" robustness claim should be checked against an eval setup designed to prevent such memorization-based inflation.
- Across both winning systems, the consistent architectural pattern is: *don't hand raw ASR output to the state tracker* — insert a dedicated correction/normalization stage first, with special-cased handling for categories of entities that ASR systematically mangles (numbers, times/dates, proper nouns/named entities). This is a reusable, domain-general pattern (the correction stage targets *types of tokens that are hard for ASR*, not *types of tokens specific to the restaurant/hotel/train domain*), so it should transfer to a task-agnostic conversational-integrity layer even though the published systems were evaluated only on MultiWOZ's specific domains.
- The repeated emphasis (OLISIA, the "Is one brick enough" paper) that WER is a bad proxy and that uncertainty from prior turns should be explicitly modeled, rather than collapsed into a single best-guess transcript before DST ever sees it, suggests the field is moving (unevenly) toward carrying *uncertainty* through the pipeline rather than fully committing to one ASR hypothesis before state tracking even starts. This is still an active research direction, not settled practice — see the next question.

### Gaps
- Could not directly fetch the primary DSTC11 track overview paper (aclanthology.org/2023.dstc-1.10, isca-archive.org, arXiv — all blocked in this environment), so the two different JGA-degradation figures (58.1→47.2 vs. 53.8→26.1) could not be reconciled against the primary source to determine which evaluation condition (which test subset, which year's report, whose paper) each belongs to. This should be flagged to the report writer as needing primary-source verification before being quoted as a headline statistic, since the two numbers tell a meaningfully different story about severity.
- Did not find explicit discussion in the speech-aware DSTC11 papers of **N-best list** or **ASR confidence score** features being fed into the DST model itself (as opposed to being used only inside the ASR-correction module) — my searches surfaced ASR-error-correction, post-processing, and data augmentation as the three named mitigations, but not confidence-score-conditioned DST specifically within the DSTC11 track papers themselves. (Confidence-aware DST does appear in older pre-neural literature — see "Encoding Word Confusion Networks with RNNs for Dialog State Tracking," arXiv 1707.05853, which predates DSTC11 and works with word confusion networks/N-best ASR lattices rather than single-best transcripts — but I could not confirm whether DSTC11 track entrants adopted this older confusion-network idea.)

## Is a fixed slot/value ontology fundamental to DST, or a benchmark-construction convenience? What schema-agnostic/open-ended alternatives exist?

### Takeaway
The literature itself does not treat a fixed slot/value ontology as fundamental — it is widely understood as a simplification needed to build an automatically-scorable benchmark (MultiWOZ, SGD) — and there is an active, explicitly-named line of work ("ontology-free," "schema-agnostic," "beyond ontology") using LLMs and description-driven schemas to track state without a hand-compiled fixed slot/value list; however, this line of work is recent (2022–2025), not yet mature/standardized, and is evaluated by comparing against fixed-ontology benchmarks, so it hasn't fully escaped the fixed-schema evaluation paradigm even as it escapes the fixed-schema modeling paradigm.

### Cited Findings
- The Schema-Guided Dialogue (SGD, DSTC8) paradigm was explicitly designed to address the scalability problem of fixed, hand-built ontologies: rather than hard-coding slot names and value lists per domain, it supplies the model with a schema of hierarchical, natural-language task-relevant descriptions, so a single model can read a new service's schema and operate on it — an explicit field-level acknowledgment that hard-coded ontologies don't scale to new domains/services. — [search aggregation re: SGD](https://www.researchgate.net/publication/339041224_Schema-Guided_Dialogue_State_Tracking_Task_at_DSTC8)
- D3ST extends this further by using randomized integer indices in place of literal slot/intent names in its description prompts specifically *because* slot names "convey little semantic information and may be ambiguous" — i.e., the model is trained not to rely on fixed slot-name strings at all, only on the natural-language description, which the authors show improves zero-shot transfer to unseen services/slots. — [arXiv pdf/2201.08904](https://arxiv.org/pdf/2201.08904)
- "Beyond Ontology in Dialogue State Tracking for Goal-Oriented Chatbot" (Lee, Kim & Song, ICKG 2024) states explicitly that "existing DST methods often rely on fixed ontologies and manually compiled slot values, limiting their adaptability to open-domain dialogues," and proposes an LLM-based approach (instruction tuning + prompting strategies including Chain-of-Thought, plus an anti-hallucination mechanism and a Variational Graph Auto-Encoder to predict likely subsequent user intent) that does not depend on any predefined ontology, reporting 42.57% JGA, stated to outperform existing ontology-less DST models. — [arXiv abs/2410.22767](https://arxiv.org/abs/2410.22767)
- "Large Language Models as Zero-shot Dialogue State Tracker through Function Calling" (FnCTOD; Li, Chen, Ross, Huber et al., ACL 2024) reframes DST as an LLM function-calling problem, enabling zero-shot adaptation to diverse domains "without extensive data collection or model tuning," and reports that in-context prompting lets 7B/13B open models surpass prior ChatGPT-based SOTA, and improves ChatGPT's own JGA by 5.6 points on average — evidence that schema/domain information can be supplied dynamically (as a function/tool spec) at inference time rather than baked into a fixed trained ontology. — [arXiv abs/2402.10466](https://arxiv.org/abs/2402.10466)
- A "Zero-Shot Open-Vocabulary Pipeline for Dialogue Understanding" is listed among recent work explicitly targeting dialogue understanding without a fixed, pre-defined vocabulary/ontology constraint. — [arXiv html/2409.15861v1](https://arxiv.org/html/2409.15861v1) *(title/positioning only — could not fetch full text; see Gaps)*

### Inferences
- There's a clear trajectory in the literature: fixed ontology (early MultiWOZ-era classification/span models) → schema-as-input but still externally-defined (SGD, D3ST — "schema-guided") → schema-free/ontology-free, LLM-driven inference of state directly from context (2024-era "beyond ontology," FnCTOD). This is a genuine architectural progression, not just relabeling, because each step removes a stronger assumption: classification models need a fixed *value* list; span/generative models need a fixed *slot* list but open values; schema-guided models need a slot list but it can change between tasks/services if descriptions are supplied; ontology-free/LLM approaches need neither a fixed slot list nor fixed value list, inferring both from context and (optionally) general intent-type reasoning.
- Despite this progression, I found no evidence of a widely-adopted *evaluation* methodology for schema-free DST that itself avoids a fixed-schema ground truth — the "Beyond Ontology" paper's own reported metric is still JGA (which, as a metric, presupposes a ground-truth set of discrete slot:value pairs to score against). This suggests: schema-freedom in the *model* is more mature/established than schema-freedom in *evaluation methodology*, which remains an open, actively-debated problem. A task-agnostic conversational-integrity layer that wants to claim schema-independence will likely need its own non-JGA-style evaluation approach, since it can't borrow one ready-made from this literature.
- This body of work directly answers the brief's framing question: a fixed slot-schema is NOT treated in the literature as a fundamental requirement of dialogue-state tracking as a *concept* — it is explicitly named (by SGD's and "Beyond Ontology"'s own authors) as a scalability/adaptability limitation of earlier approaches, and multiple independent 2022-2025 lines of work exist specifically to remove that assumption.

### Gaps
- Could not fetch full text of "A Zero-Shot Open-Vocabulary Pipeline for Dialogue Understanding" (2409.15861) or the "Beyond Ontology" paper itself (both on blocked domains); claims about these are limited to title/abstract-level search snippets, so I could not report their exact mechanism in the same depth as D3ST/FnCTOD. If a tighter architectural comparison between schema-free approaches is needed, these should be fetched directly (e.g., via an alternate access path/proxy, or by the report-writer if they have different network access).
- I did not find discussion, in this literature, of what happens to "slot-filling-equivalent" structure entirely — i.e., whether any schema-free approach represents state as something other than a (possibly dynamically-named) set of key-value pairs. All schema-free approaches found still ultimately emit something isomorphic to slot:value pairs (just without a pre-committed fixed list of keys); I found no work proposing a genuinely non-slot-shaped state representation (e.g., a free-text belief summary, a graph without key:value typing, etc.) within mainstream DST. This may be a genuine gap in the literature rather than a search failure — worth flagging to the broader synthesis as a possible novel contribution space.

## How does this literature handle a user contradicting, retracting, or changing a previously stated value? Is there confidence/multiple-hypothesis persistence, or a single committed belief?

### Takeaway
Mainstream DST (classification/span/generative/SOM-DST-style) treats state as a single committed belief that gets overwritten on the next turn when new information arrives, with no first-class "retract" or multi-hypothesis-over-time operation; explicit handling of contradiction/correction is a recognized gap called out by name in specific papers (negative-feedback-utterance work, RSP-DST's "revisable" framing), and multi-hypothesis/confidence representations exist mainly in two separate, non-mainstream lineages — pre-neural probabilistic belief tracking and recent LLM-confidence-calibration work — that have not been fully merged into the dominant single-best-state-per-turn paradigm.

### Cited Findings
- Older pre-neural/early-neural DST (e.g., the Neural Belief Tracker, Mrkšić et al. 2017) explicitly maintained, for each slot, a full probability distribution over candidate values rather than a single committed value — the framing was "maintaining a probabilistic representation of the user's goals, constraints and requests as a dialogue unfolds," predicting a probability distribution per slot per turn. — [arXiv html/1606.03777v2](https://arxiv.org/html/1606.03777v2)
- The modern (MultiWOZ-era, SOM-DST-style) DST paradigm, by contrast, is reported as generally overconfident: in a multidomain setting such as MultiWOZ, discriminative models achieve an accuracy of only "just over 55%," meaning roughly 45% of the time the prediction is wrong — and the model is typically fully confident in that wrong prediction (no well-calibrated uncertainty signal is exposed for the wrong cases). — [search aggregation re: calibration literature](https://arxiv.org/pdf/2010.02586)
- "Knowing What You Know: Calibrating Dialogue Belief State Distributions via Ensembles" (Findings of EMNLP 2020) is specifically motivated by this overconfidence problem and proposes ensembling to produce better-calibrated belief-state confidence estimates — direct evidence that *confidence calibration for DST* is treated as a real, separate research problem rather than something solved by mainstream DST architectures. — [ACL 2020.findings-emnlp.277](https://aclanthology.org/2020.findings-emnlp.277.pdf); [arXiv pdf/2010.02586](https://arxiv.org/pdf/2010.02586)
- "Toward Real-life Dialogue State Tracking Involving Negative Feedback Utterances" (Yang et al., KDD 2022) states plainly that "most current research completely ignores user negative feedback utterances that exist in real-life conversations when a system error occurs" — i.e., when the user corrects a prior system misunderstanding (their example: the system mis-hears "Indian food" as "Italian food" and the user corrects it) — and proposes defining an explicit schema of negative-feedback-utterance types plus joint modeling of feedback generation/filtering as a way to make DST responsive to in-conversation corrections. — [ACM 10.1145/3534678.3539385](https://dl.acm.org/doi/10.1145/3534678.3539385); [OpenReview Ls5KJ82ZtgL](https://openreview.net/pdf?id=Ls5KJ82ZtgL)
- RSP-DST ("Revisable State Prediction for Dialogue State Tracking") is framed explicitly around making the SOM-DST-style operation-based state update *revisable*, implying the baseline SOM-DST-style commit is treated by this later paper as effectively non-revisable/one-shot once made. — [MDPI 2079-9292/12/6/1494](https://www.mdpi.com/2079-9292/12/6/1494)
- MultiWOZ 2.1's own annotation-correction analysis independently confirms that value *changes* (valueA→valueB, value→dontcare, value→none) are a real but relatively rare category of ground-truth state transition in the data (0.44%, 0.23%, 0.17% of corrected values respectively, vs. 98.16% "no change"), suggesting such contradiction/correction turns are a minority class in the benchmark itself, which may partly explain why mainstream DST models and metrics haven't prioritized robust contradiction-handling as much as raw slot-filling accuracy. — [search aggregation of MultiWOZ 2.1 paper](https://arxiv.org/pdf/1907.01669)
- Recent LLM-based DST work has revived the confidence question: "Confidence Estimation for LLM-Based Dialogue State Tracking" (Sun, Dey, Hakkani-Tur & Tur, IEEE SLT 2024) evaluates four confidence-scoring methods (softmax probabilities, raw token scores, verbalized/self-reported confidence, and combinations, plus a "self-probing" mechanism for closed models) specifically because "well-calibrated confidence scores are essential to handle uncertainties" in DST, and uses AUC to measure calibration quality — again treating confidence/uncertainty estimation as a bolt-on addition to LLM-based DST rather than something the base architecture provides natively. — [arXiv abs/2409.09629](https://arxiv.org/abs/2409.09629)
- The "Is one brick enough..." spoken-DST paper (2023) explicitly recommends that training procedures for context propagation in DST "account for the previous[ turn]'s context inherent uncertainty" — i.e., it argues that uncertainty about the *prior* state (not just the current turn's input) should be explicitly modeled and propagated forward, rather than collapsing to one committed state after every turn — framed as an avenue for *future* work, not an established practice. — [arXiv abs/2311.04923](https://arxiv.org/abs/2311.04923)

### Inferences
- There is a real split in this literature between two unmerged lineages: (1) early/pre-neural probabilistic belief tracking, which natively represented multiple hypotheses as a distribution per slot but didn't scale well to large multi-domain ontologies and fell out of favor as the field moved to MultiWOZ-scale generative/classification DST; and (2) the dominant modern lineage (SOM-DST and its generative/span/schema-guided/LLM descendants), which commits to a single best state per turn and treats confidence/calibration/revisability as a separate add-on problem, addressed unevenly across several independent papers (calibration ensembles, negative-feedback modeling, RSP-DST's revisability, LLM confidence estimation) rather than as a built-in architectural property.
- This strongly suggests that "persisting multiple hypotheses with confidence across turns, with explicit support for contradiction/retraction" is a genuinely open, actively-debated area rather than settled practice anywhere in the mainstream DST literature — no single paper found treats this as solved; each paper found addresses one facet (calibration, or feedback-utterance detection, or revisability, or uncertainty propagation) in isolation, which is itself useful signal: a task-agnostic conversational-integrity layer that unifies confidence + revisability + contradiction-detection into one coherent mechanism would likely be a genuine architectural contribution relative to this literature, not a reimplementation of an existing unified design.
- The fact that value-change turns are a small minority of MultiWOZ ground truth (combined ~0.84% of all corrected-value cases) is a useful caution: standard DST benchmarks may systematically under-represent contradiction/correction behavior relative to what a real voice-AI deployment would see, so benchmark-reported JGA numbers likely overstate how well current architectures would handle a contradiction-heavy real-world distribution.
